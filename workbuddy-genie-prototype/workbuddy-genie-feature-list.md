# WorkBuddy 接入 Genie 能力原型功能点梳理

## 背景

当前原型地址：<https://app-builder.sg.agentos-app.run>

目标是在 WorkBuddy 的**代码开发**场景中接入 Genie 的应用生成能力，让用户可以在 WorkBuddy 内完成网页开发、小程序开发、产品原型、游戏创建。

## 整体方案

- 把genie的网页开发、小程序开发、产品原型、游戏创建，作为子场景接入
- 在这四个场景下，保留genie的差异性能力，主要是预览、云服务、设计系统、部署发布、复制到figma、下载代码、版本管理、可视化编辑
- 遵循融入workbuddy的整体框架、专家、技能、链接器、项目列表


## 一、首页入口

| 功能点 | 原型表现 | 复用 WorkBuddy | 复用 Genie |
|---|---|---|---|
| 一级能力入口 | 选中 `代码开发` | `代码开发 / 日常办公 / 设计创意` 一级胶囊体系 | 无 |
| 生成类型胶囊 | 在代码开发下展示 `网站开发 / Agent 应用 / 小程序开发 / 产品原型 / 游戏` | 胶囊样式、横向滚动、点击交互 | 类型定义、类型对应的生成能力 |
| 类型示例 prompt | 点击类型胶囊后出现示例 prompt | 示例卡片承载样式、输入框联动 | 示例内容、prompt 模板、类型上下文 |
| Chat 输入框 | 输入需求，底部有 Agent、模型、技能等控件 | 输入框结构、附件、Agent、模型、技能、发送逻辑 | 根据类型改变生成上下文和引导文案 |

## 二、Chat 生成流程

| 功能点 | 原型表现 | 复用 WorkBuddy | 复用 Genie |
|---|---|---|---|
| 用户需求输入 | 用户输入网站/小程序/原型/游戏需求 | WorkBuddy 原有消息发送和会话上下文 | 类型化需求解析 |
| 需求澄清 | 出现“你想构建什么类型的应用？”等选择卡片 | 对话流、卡片承载、消息样式 | 澄清问题、选项、分步需求确认 |
| 深度思考 | AI 输出生成计划和功能说明 | 过程消息、任务状态展示 | 生成方案、任务拆解 |
| 生成进度 | 显示“已完成 N 个任务”等状态 | 任务进度、过程状态 | Genie 的应用生成任务流 |
| 继续修改 | 用户可继续在 chat 中输入修改需求 | WorkBuddy 多轮对话 | Genie 根据修改重新生成或增量修改 |

## 三、项目页框架

| 功能点 | 原型表现 | 复用 WorkBuddy | 复用 Genie |
|---|---|---|---|
| 项目页三栏结构 | 左侧任务、中间 chat、右侧工作区 | WorkBuddy 项目页整体框架 | 无 |
| 左侧任务列表 | 最近任务、当前任务高亮 | WorkBuddy 任务和工作空间体系 | 任务类型标签可来自 Genie |
| 中间 chat | 展示需求、思考、澄清、进度 | WorkBuddy 对话流、输入框、模型/技能控件 | Genie 生成过程内容 |
| 右侧工作区 | 展示预览、产物、设计、代码、云服务 | WorkBuddy 右侧项目工作区容器 | Genie 应用生成产物 |

## 四、右侧工作区功能

| 功能点 | 当前原型表现 | 复用 WorkBuddy | 复用 Genie |
|---|---|---|---|
| 预览 | 应用预览区域、页面选择、编辑入口 | 右侧工作区容器、浏览器/预览承载 | 实时预览、页面列表、可视化编辑 |
| 产物 | features.md、design system.md 等文档 | WorkBuddy 原有产物概念和制品列表 | Genie 生成的 PRD、设计系统、HTML/应用产物 |
| 设计 | 颜色、字体、组件、卡片等设计系统 | 面板承载、查看能力 | Genie 设计系统生成、复制到 Figma |
| 代码 | 文件树 + 代码编辑器 | 建议合并到 WorkBuddy `全部文件` | Genie 生成代码内容 |
| 云服务 | 数据库、存储、用户、数据表 | 面板承载、权限和项目上下文 | Genie 云服务配置、数据库/存储/认证 |
| 发布 | 右上角 `发布` 按钮 | 顶部操作区、权限、状态提示 | 构建、部署、访问链接生成 |
| Figma / 下载 | 右上角 Figma 图标、下载入口 | 顶部操作入口样式 | 复制到 Figma、下载代码 |

## 五、建议的最终右侧 Tab

当前原型右侧 tab 为：

```text
预览 / 产物 / 设计 / 代码 / 云服务
```

WorkBuddy 原项目页已有：

```text
产物 / 全部文件 / 变更 / 浏览器
```

建议最终合并为：

```text
预览 / 产物 / 设计 / 云服务 / 全部文件 / 变更 / 浏览器
```

说明：

- `预览`：新增 Genie 能力，用于展示应用运行效果。
- `产物`：保留 WorkBuddy 产物概念，承载 Genie 生成的 PRD、设计系统、应用包等。
- `设计`：新增 Genie 能力，用于展示设计系统和复制到 Figma。
- `云服务`：新增 Genie 能力，用于数据库、存储、认证、部署配置。
- `全部文件`：复用 WorkBuddy，展示 Genie 生成的代码文件。
- `变更`：复用 WorkBuddy，展示每轮 Genie 生成/修改带来的文件 diff。
- `浏览器`：复用 WorkBuddy，用于调试、打开发布链接、验证页面。

## 六、需要调整的点

1. `代码` 不建议作为独立新 tab。
   - 原因：它与 WorkBuddy 的 `全部文件` 能力重叠。
   - 建议：将 `代码` 内容并入 `全部文件`，tab 名称沿用 WorkBuddy。

2. 需要补回 `变更`。
   - 原因：WorkBuddy 原项目页中有变更管理能力。
   - 建议：展示 Genie 每轮生成、修改、可视化编辑带来的文件 diff。

3. 需要补回 `浏览器`。
   - 原因：WorkBuddy 原项目页中有浏览器能力。
   - 建议：用于调试、打开发布链接、验证页面行为。

4. `发布` 应固定在右侧工作区右上角。
   - 原因：发布属于项目级操作，不应只藏在 chat 卡片里。
   - 建议：保留 chat 中的发布结果卡片，但入口放在右上角。

5. `复制到 Figma` 和 `下载代码` 应作为 Genie 特有交付能力。
   - 建议：放在右上角下载/更多操作中，不替代 WorkBuddy 原有文件能力。

## 八、推荐接入方式

推荐采用“WorkBuddy 外壳 + Genie 能力内核”的方式：

```text
WorkBuddy 首页
→ 代码开发
→ 选择 Genie 类型胶囊
→ WorkBuddy Chat 承接需求
→ Genie 进行需求澄清和应用生成
→ WorkBuddy 项目页承载结果
→ 右侧工作区使用 Genie 的预览、设计、云服务、发布能力
→ 文件、变更、浏览器继续复用 WorkBuddy
```

这样可以避免做成一个独立 Genie 页面嵌入 WorkBuddy，也能最大程度保留 WorkBuddy 原有工作流。
